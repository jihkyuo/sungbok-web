# 예배 설교 영상 (`/worship/sunday` 등)

예배 메뉴는 **영상을 보러 들어오는 곳**이다. 관리자는 유튜브에 올리기만 하고, 사이트는 유튜브에서 읽어 자동으로 분류한다.
화면은 두 페이지다(2026-11-13, 시안 G 의 한 페이지를 둘로 나눔 — 옆 「설교 목록」과 아래 찾기 목록이 같은 일을 해서).

| 페이지 | 주소 | 내용 |
|---|---|---|
| 설교 목록 | `/worship/sunday` | 「최신 설교」 한 편 + 검색·시리즈 칩·정렬이 되는 설교 목록(「설교 더보기」) |
| 설교 한 편 | `/worship/sunday/영상id` | 유튜브 플레이어 · 제목 · 이전·목록·다음 · 설명란 · 「설교 목록」(시리즈 칩과 회차) |

> 계획·결정 배경: [specs/2026-11-12-worship-sermon-g-plan.md](../specs/2026-11-12-worship-sermon-g-plan.md)(G안 — 데이터·운영 규칙은 그대로, 화면 배치만 위 표로 바뀜)

## 운영 규칙 — 유튜브에 이렇게 올리면 된다

| 무엇 | 규칙 | 사이트에서 |
|---|---|---|
| 어느 예배 페이지 | 예배별 **유튜브 재생목록**에 넣는다(주일예배 = 「주일 예배 설교」) | 그 페이지에 나온다. 연결은 코드 설정([worshipPages.ts](../../src/domains/worship-video/config/worshipPages.ts)) |
| 시리즈 | 제목을 `시리즈 이름 N \| 제목 \| 본문 \| 설교자` 로 | 「설교 목록」에 시리즈 칩이 생기고 `N편` 으로 묶인다 |
| 단편(절기·주제) | 제목 첫 칸에 회차 번호가 없으면 단편 — `성찬식 \| 제목 \| 본문 \| 설교자`, `제목 \| 본문 \| 설교자` | 「단편 설교」 칩 하나로 모인다. 첫 칸(성찬식 등)은 분류 표시로 보인다 |
| 설교일 | 설명 **첫 줄**에 `2026년 10월 25일 …` | 그 날짜로 정렬·표시. 없으면 유튜브 **업로드 날짜**를 쓰고 「업로드 2026.10.25」로 표시(설교일이 아닐 수 있어서) |
| 설교자 | 제목 마지막 칸(`… \| 이요셉 목사`) | 목록 페이지의 「최신 설교」에 「설교 이요셉 목사」로 보인다. 없으면 그 줄을 그리지 않는다 |
| 설명 | 자유롭게 | 플레이어 아래에 그대로(첫 줄이 날짜면 그 줄은 숨김). `#` 으로 시작하는 줄은 색만 다르게 |

- 본문·설교자 칸은 빠져도 된다(`시리즈 N | 제목 | 설교자`). 형식 밖 제목은 제목 전체가 그대로 보이고 단편으로 간다 — 목록에서 빠지지는 않는다.
- 시리즈 이름은 띄어쓰기만 달라도 같은 시리즈로 묶는다(「마태복음 강해」·「마태복음강해」 → 가장 최근 편의 표기). 회차는 세 자리까지 — 「송구영신예배 2026」의 연도는 회차로 읽지 않는다.
- 네 칸을 다 채우면 마지막 칸은 직분과 상관없이 설교자로 읽는다(초청 설교자 「홍길동 집사」, 「성복교회 이요셉 목사」).
- 시리즈 안의 순서(회차 목록·이전/다음 편)는 날짜가 아니라 **회차 번호**로 정한다. 단편 설교는 단편끼리 날짜 순.
- 설정에 없는 재생목록(예배 찬양, 장별 마태복음 등)은 어디에도 나오지 않는다.
- 반영 시점: 유튜브 응답 1시간 캐시 + 페이지 10분 재생성 → 올린 뒤 **최대 약 1시간 10분**.

## 페이지·앱 복귀

- 설교 목록과 설명은 사용하지 않는 동안에도 30분 동안 브라우저 메모리에 보관한다(`gcTime`). 10분의 최신 여부 기준(`staleTime`)은 유지한다.
- 다른 페이지에서 돌아오면 받은 자료를 먼저 표시한다. 오래된 자료를 다시 확인하는 동안에도 현재 화면을 로딩 상태로 교체하지 않는다.
- 일반 앱·탭 전환으로 문서가 유지되면 기존 React 트리와 영상 프레임을 그대로 사용한다. OS가 탭을 폐기한 경우는 새 문서 로드이므로 이 메모리 캐시 정책만으로 재로딩을 없앨 수는 없다.

## 구조

```
유튜브 playlistItems(snippet,contentDetails) ──1시간 Data Cache──▶ worshipVideo.server.ts
   제목·설명 읽기(sermonParse) → Sermon[] (최신순) + 설명 본문(Map)
        │
        ├─ 목록 페이지(ISR 10분)   : widgets/SermonLibrary → prefetchSermonLibrary → 목록 전체를 HTML 에
        ├─ 설교 한 편(ISR 10분)    : widgets/SermonWatch   → prefetchSermonWatch   → 목록 전체 + 그 설교의 설명
        │      빌드 때는 만들지 않고 처음 열릴 때 만든다. 목록에 없는 영상 id 는 404(`[videoId]/not-found.tsx`).
        │      유튜브를 못 받아도 던지지 않는다 — 처음 열리는 설교는 «직전 성공본» 이 없어 던지면 오류 화면이 된다.
        │      못 받은 것은 화면이 /api 로 받는다
        └─ Route Handler: /api/worship-video/library?page=   (서버가 못 실었을 때 화면이 받음)
                          /api/worship-video/description?page=&v=   (그 영상의 설명 — 목록에 있는 영상만)
화면: 검색·시리즈·정렬·더보기·이전/다음은 받은 목록으로 화면에서(sermonList) — 유튜브를 다시 부르지 않는다
```

| 파일 | 맡은 일 |
|---|---|
| `config/worshipPages.ts` | 예배 페이지 ↔ 재생목록 id, 주소 만들기(`sermonPath`). 다른 예배 페이지를 열 때 한 줄 추가 |
| `api/sermonParse.ts` | 제목·설명 → 시리즈·회차·본문·설교자·설교일(순수) |
| `api/sermonList.ts` | 정렬·검색(「12장」 → `12:`)·시리즈 묶기·이전/다음 편·목록 줄(`listRows`)·표시 문구(순수) |
| `api/worshipVideo.server.ts` | 유튜브에서 모으기(서버 전용). 업로드 시각 → 한국 날짜는 여기서(Temporal, [ADR 0012](../decisions/0012-date-temporal-and-admin-libraries.md)) |
| `api/useSermonLibrary.ts` | 화면 훅(목록·설명) |
| `api/sermonListState.ts` | 목록 페이지의 검색어·시리즈·정렬·보인 편수를 화면 밖(모듈)에 둔다 — 설교를 보고 돌아와도 그대로. 「목록」으로 돌아올 스크롤 자리도 여기 |
| `api/playIntent.ts` | 설교 링크를 누를 때 다음 화면에 남기는 표시 — 「들어오자마자 재생」(설교 페이지가 읽고 지운다: 뒤로·앞으로 가기로 다시 들어오면 재생하지 않는다)과 「이전·다음 중 어느 쪽을 눌렀나」(새 화면이 같은 쪽 링크에 포커스를 되돌린다). 새 탭으로 여는 클릭(Cmd·Ctrl 등)은 남기지 않는다 |
| `api/useYoutubePlayState.ts` | 유튜브 플레이어가 재생 중인지(postMessage, `enablejsapi=1`) — 「재생 중」 표시용 |
| `components/features/SermonListPage` | 목록 페이지 = `SermonLatest`(최신 설교) + `SermonList`(검색·칩·정렬·목록) |
| `components/features/SermonWatchPage` | 설교 한 편 = `SermonPlayer` + `SermonInfo`(제목·이동·설명·시트지·공유) + `SermonSidebar`(설교 목록) |

## 화면 규칙

**목록 페이지**

- **최신 설교**: 표지 + 「최신 설교」·날짜·요일(일요일은 「주일」)·제목·본문·설교자·「설교 시청하기」. 표지와 버튼은 같은 곳으로 가므로 키보드·화면낭독기에는 버튼 하나만 보인다.
- **설교 목록**: 검색(치는 대로 걸러짐, 검색 버튼 없음) · 시리즈 칩(전체 + 모든 시리즈, 한 줄 — 넘치면 옆으로 넘기고 태블릿·PC 는 넘길 쪽에 화살표) · 최신순/오래된 순.
- 조건이 없는 첫 화면에서는 위에 크게 보인 최신 설교를 목록에서 뺀다(편수 표시는 전체). 조건을 걸면 결과에 나온다.
- 처음 12편, 「설교 더보기」를 누를 때마다 12편씩. 다 보이면 버튼이 사라진다. 결과가 없으면 「검색 결과가 없습니다.」
- 설교를 누르면 그 설교 페이지로 넘어가 바로 재생된다. 설교 줄은 미리 받지 않는다(`prefetch={false}`) — 설교 페이지에는 목록 전체가 실려 있어 줄 수만큼 내려받게 된다.

**설교 한 편 페이지**

- **플레이어**: 처음부터 유튜브 플레이어(`youtube-nocookie`)를 둔다 — 우리 재생 버튼(포스터)을 따로 두면 그 버튼을 눌러도 브라우저(특히 아이폰)가 소리 나는 자동재생을 막아 유튜브 재생 버튼을 한 번 더 눌러야 한다. 설교를 눌러 넘어온 경우에만 자동재생을 요청하고(`autoplay=1`), 주소로 바로 들어오면(공유 링크·새로고침) 멈춘 채로 뜬다.
- 설교 페이지는 **설교마다 새로 만들어진다**(Next 가 주소의 영상 id 로 화면을 가른다) — 설교 사이에 이어져야 하는 것(재생 요청, 이전/다음 포커스)은 화면 안의 상태가 아니라 `playIntent` 에 둔다.
- **이전 · 목록 · 다음**: 분류 표시 오른쪽의 작은 알약 셋. 시리즈는 회차 번호(「64편」), 단편 설교는 「이전」·「다음」. 끝 편은 그쪽이 흐린 글자(「첫 편」·「최신 편」). 「목록」은 목록 페이지의 보던 자리·조건으로 돌아간다.
- **링크 복사 · 유튜브에서 보기**: 태블릿·PC 는 분류 표시 옆의 작은 알약, 휴대폰은 설명·시트지 아래의 두 칸짜리 버튼.
- **설교 목록**(PC 는 옆, 그 밖에는 아래): 최근 시리즈 칩 4개 + 「전체 N개」(연도별 고르기). 칩을 바꿔도 보던 영상은 계속 재생된다. 휴대폰은 회차를 옆으로 미는 한 줄, 태블릿은 3칸 + 화살표, PC(lg 이상)는 플레이어 옆 세로 목록.
- 지금 보는 설교의 썸네일에는 늘 표시가 붙는다 — 재생 중이면 「재생 중」, 아니면 「현재 영상」. 재생 여부는 플레이어가 알려 주는 상태를 따르고, 끝내 알 수 없으면(광고 차단기 등) 눌러서 넘어온 설교를 재생 중으로 본다.
- 눌러서 넘어왔는데 플레이어부터 이동 버튼까지 한 화면에 안 들어오면(서브페이지 머리가 크다) 플레이어가 맨 위에 오게 맞춘다. 주소로 바로 들어오면 맨 위 그대로.
- 설교 시트지: `SermonInfo` 의 `sheetHref` 자리만 있다 — 관리자 업로드가 생기면 연결한다.

## 미결·다음

- 금요·특별집회·수요새벽 페이지: `worshipPages.ts` 에 재생목록을 더하고 `app/worship/<페이지>/page.tsx`(`<SermonLibrary page="…" />`)와 `[videoId]/page.tsx`(`<SermonWatch page="…" />`)·`not-found.tsx` 를 두면 같은 화면이 나온다(재생목록 후보는 그 파일 주석).
- 설교 페이지에도 목록 전체가 실린다(옆 목록·이전/다음용). 긴 재생목록을 열 때는 목록 싣기를 `app/worship/<페이지>/layout.tsx` 로 올려 설교 페이지에는 설명만 싣는 구조를 검토한다.
- 어제(2026-11-12) 잠깐 쓰인 `?v=영상id` 주소는 더 지원하지 않는다(목록 페이지가 열린다).
- 재생목록이 매우 길 때(새벽예배 800편대): 목록 글자 정보는 압축 20KB 안팎이라 전부 실어도 된다(2026-11-13 실측·추정). 다만 설교 한 편 페이지의 「설교 목록」은 고른 시리즈의 편을 한꺼번에 그린다 — 한 분류에 수백 편이 들어가는 페이지를 열 때 나눠 그리게 고친다. 설명 API 도 요청마다 목록 전체를 캐시에서 다시 조립하므로(유튜브 쿼터는 쓰지 않음) 그때 함께 본다.
