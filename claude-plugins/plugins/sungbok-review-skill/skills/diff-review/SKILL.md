# diff-review — 변경분 코드 리뷰

성복교회 웹(Next.js 15 App Router + TS + Tailwind 4) 변경분을 커밋/PR 전에
자가검증하는 리뷰 방법론. **리뷰만 한다 — 코드를 수정하지 않는다.** 발견 사항을
리포트로 돌려주고, 수정은 사용자/구현자가 판단한다.

## 0. 대상 파악

리뷰 범위를 먼저 확정한다.

1. 인자로 특정 파일·디렉토리·범위가 주어졌으면 그쪽을 우선 대상으로 삼는다.
2. 아니면 작업트리 전체 변경분을 대상으로 한다:
   - `git diff` — unstaged 변경
   - `git diff --staged` — staged 변경
   - `git status --short` — 신규/삭제 파일 파악
3. 변경된 함수·컴포넌트는 **diff 라인만 보지 말고 파일 전체와 호출부까지 Read**
   해서 맥락을 잡는다. 시그니처·주석·한 줄 호출만 보고 결론 내지 않는다.

변경이 하나도 없으면 그 사실을 보고하고 종료한다.

## 1. 체크 항목

### (1) 정확성 버그 — 최우선
- 로직 오류, off-by-one, 잘못된 조건/부정.
- `null`/`undefined`/빈 배열 등 경계값 미처리.
- `async`/`await` 누락, Promise 미대기, 경쟁 상태·타이밍.
- 에러 처리 누락 또는 과잉(일어날 수 없는 시나리오 방어).
- React 특화: 의존성 배열 누락/과다, key 누락, 조건부 훅, 서버/클라이언트
  컴포넌트 경계, 하이드레이션 불일치(과거 회귀 이력 있음).

### (2) 재사용 · 단순화
- 기존 유틸·컴포넌트가 있는데 새로 짠 중복 로직 → 기존 것 재사용 제안.
  (`src/shared/`, 해당 도메인 내부를 Grep으로 먼저 확인)
- 오버엔지니어링: 요청되지 않은 추상화·"유연성"·설정 가능성.
- 200줄로 짠 것이 50줄로 되는지. "시니어가 보면 과하다 할까?" 자문.

### (3) 프로젝트 컨벤션
- **도메인 구조**: `src/domains/<domain>/components/{features,widgets}` 배치가 맞는지.
- **공유 컴포넌트**: 도메인 공용은 `src/shared/components/`.
- **전역 토큰만 사용**: 컬러·폰트·반경 HEX 하드코딩 금지. `globals.css`의
  `@theme inline` 토큰을 Tailwind 유틸(`bg-b1-accent`, `text-b1-sub` 등)로 참조.
- **한글 가독성**: `word-break: keep-all`(globals.css 전역 적용), 헤딩
  `text-wrap: balance` 전제. 깨는 인라인 스타일 없는지.
- 디자인 토큰을 `globals.css`에서 바꿨다면 `.md/design/`의 짝 문서도 갱신 대상인지 지적.

### (4) 외과적 변경 점검
- 변경된 모든 라인이 요청에 직접 추적되는가.
- 요청 범위 밖 리포맷·주석 정리·무관 리팩터가 섞이지 않았는가.
- 내 변경으로 생긴 고아(미사용 import/변수/함수)는 제거됐는가. 기존부터 있던
  죽은 코드는 언급만 하고 삭제 요구하지 않는다.

### (5) 카피 톤 — 콘텐츠/문구 변경 시
- 영업/약속/환대성 멘트 배제. 사실 진술의 정중함으로만 신뢰를 형성하는 톤인지.

## 2. 깊이 규율

- **호출 체인 끝까지 추적**한 뒤 결론. 부수효과·누락 분기·타이밍을 직접 확인.
- 위험·핵심 변경은 **깨지는 시나리오 3개**를 단계별로 그려본 뒤 판정.
- 옵션 매트릭스/트레이드오프표로 결정을 떠넘기지 않는다. "이게 문제고 이유는 X,
  이렇게 고쳐라" 형태로 결론낸다.
- 확신 없는 지적은 추측으로 단정하지 말고 "확인 필요" 로 표시한다.

## 3. 출력 형식

심각도별로 그룹화해 보고한다. 각 항목은 `파일:라인` + 문제 + 제안 수정.

```
## 코드 리뷰 결과

### 🔴 must-fix (정확성·버그)
- `src/.../foo.ts:42` — <문제> / 제안: <수정 방향>

### 🟡 should-fix (재사용·컨벤션·단순화)
- `src/.../bar.tsx:13` — <문제> / 제안: <수정 방향>

### 🔵 nit (사소)
- ...

### 종합
<한 줄 판정: 머지 가능 / 수정 후 가능 / 막아야 함 + 핵심 이유>
```

지적이 하나도 없으면 그렇게 보고하고, 무엇을 확인했는지 한 줄로 남긴다.
없는 문제를 만들어내지 않는다.
