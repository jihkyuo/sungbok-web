# ADR 0013: 접속 시점 이미지 변환(`/_next/image`)을 쓰지 않는다 — 레포 사진은 크기 파일을 미리 만들고, 유튜브 썸네일은 유튜브의 크기별 주소로

**상태**: 채택
**날짜**: 2026-11-14

## 배경
ADR 0010 은 사진을 WebP 로 한 번 변환해 두되, 화면 폭별 크기 생성은 `next/image`(Vercel 변환기)에 남겼다. 근거는 «Vercel 이 변환 결과를 엣지에 캐시한다»였다.

방문이 뜸한 사이트에서는 이 캐시가 식는다. 2026-11-14 운영(`sungbok-web.vercel.app`) 실측: 서버 첫 응답 0.05~0.15초, Lighthouse 97/96 인데, 캐시에 없는 사진은 요청 시점에 변환하느라 한 장당 0.4~1.7초(캐시에 있으면 0.05~0.1초). «한동안 아무도 안 들어온 뒤 첫 접속에서 사진이 늦게 뜬다»는 증상의 원인이었다.

## 결정
- **레포 사진은 폭별 크기 파일을 미리 만들어 레포에 둔다** — `pnpm images:variants`(`scripts/photo-variants.mjs`). 폭 128·256·384·640·828·1080·1200(원본 폭의 85% 이하만), WebP 화질 85(교역자·부서 사진 `images/staff`·`images/main/department`·`images/next-generation` 은 90). 결과는 `src/assets/sized/<경로>.<원본 해시>.w<폭>.webp` 와 목록 `src/assets/photoVariants.generated.ts`. 그보다 큰 요청은 원본(최대 1920)을 준다. PNG 는 원본 크기 WebP 도 만든다.
- **화면에서는 `<Photo>`**(`src/shared/components/features/Photo`) — `next/image` 에 loader 를 주어 `srcset` 의 각 폭을 미리 만든 파일로 잇는다(`pickVariant`). `sizes`·`preload`·지연 로딩은 그대로다. 크기 파일이 없는 작은 그림은 원본을 그대로 준다. 모두 `/_next/static/media` 의 해시 주소(1년 캐시)라 변환기를 거치지 않는다.
- **파일 이름에 원본 내용 해시** — 같은 이름으로 사진을 바꾸면 옛 크기 파일은 지워지고 새로 만들어진다(«바꿨는데 작은 화면만 옛 사진» 방지).
- **빠뜨리면 빌드 실패** — `pnpm build` 가 `photo-variants.mjs --check` 를 먼저 돌린다.
- **화질은 한 곳에서** — `quality` 속성과 `next.config.ts` 의 `qualities: [75, 85, 90]` 을 없앴다. 기존 기본 75·히어로 85·교역자/부서 90 → 기본 85, 교역자·부서 사진은 90(스크립트의 `QUALITY_RULES`). 부서 페이지에서도 쓰는 `main01`·`worship`·`first-visit` 은 홈 첫 화면 사진이라 85.
- **유튜브 썸네일은 유튜브의 크기별 주소로 바로 받는다** — `<YoutubeThumb>`(`src/shared/components/features/YoutubeThumb`, `youtubeThumbLadder`). 유튜브는 영상마다 320·480·640·1280 폭 썸네일을 갖고 있어, 받은 주소(가장 큰 것)에서 더 작은 크기의 주소를 만들어 `srcset` 에 넣는다. WebP 판(`/vi_webp/`, JPG 의 절반쯤)을 먼저 쓰고 받지 못하면 JPG 로 바꾼다. 2026-11-14 사이트의 영상 178개·주소 708개 모두 존재 확인. 변환 캐시(4시간)가 없어 식을 일이 없고, 썸네일이 바뀌면 유튜브 쪽 수명대로 반영된다.
- **`next.config.ts` 의 `images`(외부 주소 허용 목록 포함)를 없앴다** — 변환기를 쓰는 곳이 없다.
- **붓글씨체는 쓰는 글자만** — `.b1-brush` 는 인사 한마디에만 쓰여, 그 글자만 담은 `src/assets/fonts/sungbok-brush.woff2`(~3KB, `pnpm fonts:brush`)를 먼저 쓴다. 조각 폰트 4개(~118KB) → 1개. `@fontsource` 조각 CSS 는 예비로 남겨, 문구를 바꾸고 다시 만들지 않아도 빠진 글자는 거기서 받는다.

## 대안 비교
- **`images.minimumCacheTTL` 을 길게** — 한 줄이지만 유튜브 썸네일이 바뀌어도 그 기간 옛 그림이 나온다. 탈락.
- **유튜브 썸네일은 변환기 유지** — 방문이 뜸하면 4시간 캐시가 매번 식어 썸네일 자리가 0.4~1.7초 비었다가 뜬다. 탈락.
- **`images.unoptimized: true`**(ADR 0010 이 남겨 둔 선택지) — `srcset` 이 사라져 휴대폰이 1920px 원본을 받는다. 이번 방식은 `srcset` 을 유지한다.
- **전역 `loaderFile`** — 유튜브 썸네일용 변환기까지 꺼진다. `<Photo>` 단위 loader 로 한정.
- **빌드 때 생성(레포에 두지 않음)** — 개발 서버·테스트도 파일이 있어야 하고 빌드가 느려진다. 기존 WebP 변환과 같은 «한 번 만들어 레포에 둔다» 방식을 따랐다.

## 결과 / 영향
- 브라우저가 `i.ytimg.com` 에 직접 접속한다 — ADR 0010 의 «외부 0곳»이 1곳이 된다(썸네일을 쓰는 화면에서 미리 연결). 유튜브 WebP 는 우리 변환본과 용량이 비슷하다(640폭 약 35KB).
- 로컬 운영 빌드 홈: `/_next/image` 요청 0(유튜브 키가 없어 썸네일은 빠진 수치 — 썸네일은 테스트와 유튜브 주소 실측으로 확인), 붓글씨 폰트 4개 118KB → 1개 3KB. 운영 효과는 배포 후 다시 잰다.
- 레포에 크기 파일 192개·약 4.9MB 가 늘었다. 사진을 넣거나 바꿀 때 `pnpm images:variants` 한 단계가 생겼다.
- 사진 목록(주소 표)이 `<Photo>` 를 쓰는 화면의 스크립트에 실린다(약 18KB, 압축 약 5KB). 사진이 크게 늘면 쓰는 사진만 싣는 방식으로 바꾼다.
- 개발 의존성 `subset-font` 추가.
- ADR 0010 의 «폭별 변환은 남겼다»·«화질 허용 목록»·«외부 0곳» 세 항목은 이 결정으로 바뀌었다(나머지는 유효).
